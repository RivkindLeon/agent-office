# Схема журнала

Единственный источник правды для «Офиса». JSONL, один файл на день:
`journal/ГГГГ-ММ-ДД.jsonl`. Строка добавляется в конец, файл не переписывается.

Имена полей по возможности повторяют семантические соглашения OpenTelemetry
GenAI (`gen_ai.agent.*`, `gen_ai.usage.*`). Мы не подчиняемся им целиком — они
про технические вызовы модели и всё ещё в статусе Development, — но там, где
смысл совпадает, имя берём их. Тогда рядом можно будет включить готовый
инструмент трассировки, не переделывая журнал.

Схему держать стабильной: старые дни должны открываться после любых изменений.
Новые поля — только необязательные.

## Поля

| Поле | Тип | Обяз. | Смысл |
|---|---|---|---|
| `ts` | ISO 8601 с зоной | да | когда произошло |
| `agent.id` | строка | да | идентификатор должности (`head-of-people`) или `founder` |
| `agent.version` | `X.Y` | да, кроме `founder` | версия пакета, по которой работал сотрудник |
| `type` | см. ниже | да | что произошло |
| `subject` | строка | нет | над чем: должность, заявка, тикет, номер PR |
| `summary` | строка ≤ 80 симв. | да | реплика в пузырь над головой персонажа |
| `detail_ref` | путь или URL | нет | куда ведёт клик |
| `outcome` | `ok` \| `idle` \| `blocked` \| `failed` | да | итог |
| `duration_ms` | число | нет | сколько заняло |
| `usage.input_tokens` | число | нет | расход по OTel |
| `usage.output_tokens` | число | нет | расход по OTel |
| `usage.model` | строка | нет | на какой модели выполнено |
| `handoff_to` | `agent.id` | только для `handoff` | кому уходит работа |

**`agent.version` — главное новшество.** Без него нельзя ответить, стало ли
лучше после правки инструкции: доля возвратов считается по версии пакета, а не
по должности вообще.

## Типы событий

**Смена:** `shift_start`, `shift_end`, `idle` (триггер не сработал, модель не
вызывалась), `blocked` (упёрлись в бюджет, зависимость или красную проверку).

**Найм:** `requisition_filed`, `package_created`, `review`, `returned`,
`approved`, `hired`, `role_review`.

**Решения основателя:** `decision`, `sanction`. Санкцию выпускает только
`founder`, и у неё обязателен `subject` — файл, правку которого она разрешает.
Действует на один файл и один день.

**Работа:** `decision`, `ticket_created`, `design_ready`, `commit`,
`pr_opened`, `ci_failed`, `merge`, `deploy`.

**Передача:** `handoff` — с обязательным `handoff_to`. Именно оно даёт в офисе
анимацию «отнёс папку соседу».

## Что из этого рисует офис

| В офисе | Откуда берётся |
|---|---|
| комната существует | в журнале есть хотя бы одно событие этой должности |
| персонаж на месте | был `shift_start` без `shift_end` |
| чем занят сейчас | последнее содержательное событие, поле `summary` |
| предметы на столе | артефакты, где должность указана автором |
| папка между комнатами | `handoff` + `handoff_to` |
| красная лампа | `failed`, `ci_failed`, `blocked`, `returned` |
| пустая комната со стулом | `idle` — приходил, работы не было |

Комнаты не заданы заранее: офис пуст, пока никого не наняли, и заполняется по
мере того, как у должностей появляются события.

## Игровые метрики

Считаются на лету, у каждой есть источник — выдумывать нельзя:

| Метрика | Источник |
|---|---|
| энергия | остаток лимита смены из `PROFILE.md` минус `usage` |
| настроение | доля `outcome: ok` за 7 дней |
| загрузка | длина входной очереди должности |
| «пошёл за кофе» | `usage.model` не основная модель должности |
| качество описания | доля возвратов по текущей `agent.version` |

## Журнал один

`journal/` — настоящие события компании, и других журналов в репозитории нет.
Синтетика для отладки живёт вне его, у прототипа основателя: метрики компании
должны считаться только по настоящему.

## Валидация

`org/tools/validate-journal.mjs` проверяет каждую строку. Битая строка не роняет
день: она пропускается и попадает в отчёт. Роль, которая пишет битые строки, —
баг роли.
